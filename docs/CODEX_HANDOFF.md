# Codex 项目交接

更新日期：2026-07-28

## 项目定位

ACG DNA Web 是从 Android APP 创作页抽离出来的前端属性图编辑器。产品无账号、无项目后端、无公开社区、无相似度对比；项目数据默认保存在浏览器本地。唯一线上服务是已获授权的受限无状态 Bangumi 网关，不保存项目或用户资料。

GitHub 仓库：https://github.com/befoer/acg-dna-web

当前仓库暂时为 Private，完成并完成安全/许可检查后再公开。源代码许可证为 MPL-2.0。

## 工作区结构

当本仓库位于作者本机的完整工作区时，以仓库根目录为基准：

- .：当前 Git 仓库（外层工作区中的 acg-dna-web 子目录）
- ../reference：精选 Android 源码、原始素材、字典、截图和工具，仅供迁移参考，不提交 Git
- ../AGENTS.md：外层工作区唯一入口与操作边界

后续 AI 必须先阅读外层 `AGENTS.md`、本文件、MVP_SCOPE.md、ONLINE_IMAGE_SEARCH.md 和外层 reference/README.md。

## 已确定产品决策

- React + TypeScript + Vite。
- Canvas 2D 负责属性图预览和高清导出。
- IndexedDB 保存项目 JSON 和图片 Blob。
- 不导入旧 Android 用户项目数据。
- 保留分类、属性、子属性三级数据。
- 保留布局、模板、资料视觉标题卡、撤销重做、自动保存和 PNG 导出。
- 资料板块按 Android APP 创作页完整复刻，但删除从账号自动载入资料和“我的主页”头像来源；头像仅从本地选择。
- 第一版在线图片搜索采用 Bangumi 中文候选解析、AniList 头像候选的两阶段流程；Bangumi 通过项目维护的受限私有网关访问，网关实现与部署配置不进入本仓库，中文词典仍延期。
- 现有 Logo、图标、模板图形均由项目作者制作并允许公开。当前仅内置采用 SIL OFL 1.1 的资源圆体；其他字体由用户从本地选择。

## UI 决策

移动端优先，尽量延续现有 APP：顶部标题/保存状态/导出，中间画布，底部模板、数据、资料、外观四个入口和可展开抽屉。标签范围已并入外观；外观同时承载自定义图片、APP 装饰素材、基础图案与矩形、统一图层、画布比例和基础描边。

PC 第一版不完整复制概念图中的双侧面板，而使用：顶部工具栏、左侧工具栏、单个 320 至 360 像素功能面板、中央自适应画布。属性设置继续在左侧面板内切换，右侧属性检查器、可调宽度面板和复杂拖放延后。

响应式工作区以 900 像素为 PC/移动布局切换点，并覆盖 375、768、1024、1440 四档目标宽度。移动端模板、数据、资料、外观四个入口固定为单行四列；375 像素窄屏下画布标题和布局选择保留首行，保存状态独占第二行并允许截断，避免长保存错误挤出画布控制。

移动端和 PC 必须共享 Editor Store、Canvas、DataPanel、TemplatePanel、ProfilePanel 和 AppearancePanel，不能维护两套业务逻辑。

## 当前实现进度

- 已完成 React + TypeScript + Vite 工程、ESLint、Prettier、Vitest、Schema v1、共享 Editor Store、三级数据编辑、本地图片、Canvas 预览与 PNG 导出。节点图片和资料头像共用非破坏式编辑器；属性图片采用长方形工作区、半透明裁切遮罩、拖动定位、移动端双指和四角缩放框，不再显示独立参数滑块与旋转按钮。原始 Blob 不重复压缩，变换参数随自动保存、撤销重做和项目文件保存，预览与 PNG 使用同一绘制函数。
- IndexedDB 已升级为多项目存储：每个项目的文档和图片 Blob 相互隔离，支持新建、切换、复制、重命名和确认删除；切换前会强制保存当前编辑，删除最后一个项目后自动创建新项目。项目面板通过 StorageManager 仅显示当前源的浏览器已用空间；自动保存失败后，PC 顶栏与移动端画布状态均提供显式重试按钮。每次成功保存会以当前资产集合替换该项目旧 Blob，删除项目也会同步删除其全部 Blob，并有 IndexedDB 回归测试覆盖。持久化初始化增加幂等保护，热更新或 Effect 重启不会再次把当前编辑另存为重复项目。项目恢复完成后会自动按忽略项目 ID/时间后的文档内容及图片 SHA-256 指纹清理异常重复项；当前项目优先保留，否则保留最近保存的一份。用户主动复制产生的“副本”名称不同，不参与自动清理。
- 数据库结构版本为 v3：升级时保留旧版 `current` 项目和旧图片表，并在新版项目库为空时复制迁移；也能修复仅有旧表的中间态 v2 数据库，迁移失败不会删除旧记录。
- 已支持带版本号的 `.acgdna.json` 项目文件：图片以内嵌 Base64 携带，导入前校验格式、Schema、版本、大小、图片引用和可解码性；成功导入为新项目，失败不覆盖当前项目。
- PC Canvas 使用统一比例完整适应可用舞台；预览支持相对适应比例 50% 至 200% 缩放，放大后只在 Canvas 视口内部滚动，导出逻辑尺寸不变。
- Canvas 设置包含 packing 和 gravity 两种布局模式；旧 Schema v1 数据缺少该字段时回退到 packing。
- gravity 使用固定步数和稳定哈希，对顶层分类、分类内属性、属性内子属性递归执行重力松弛、零间距圆碰撞和父圆边界约束。顶层通过多宽度候选、向下沉积、接触簇合并和最小必要缩放保持贴底、无重叠且尽量填满标签范围；子级按数量分配目标面积和最小半径，保留高低权重差异。带子标签的一级标题按 APP 的矩形碰撞体参与布局，避免标题压住相邻圆；相关测试覆盖极端权重、4–8 个一级标签和多项目种子。
- Canvas 支持直接选择属性圈并显示斜上方放射状操作：调整图片、添加子标签、删除标签。按钮间距随圆半径自适应；三级叶子节点隐藏无效的添加操作。添加图片后节点文字自动隐藏，容器标题位于顶部描边缺口，没有子标签的节点保持完整圆形描边。
- 数据树沿用 APP 的紧凑编辑行：节点名称旁直接显示权重滑块和数值，选中节点卡片不再重复提供独立权重输入。
- 分类、属性和子属性均可在自己的同级列表中上移或下移；排序作为独立结构编辑进入撤销重做和自动保存，边界位置不会产生空历史。
- 数据树已迁移 APP 式折叠与命名添加流程：分类和属性分支可展开/折叠，选择隐藏分支内节点时自动展开；分类添加前输入名称，属性与子属性支持单条或最多 50 项批量添加。批量文本支持换行、顿号、中英文逗号/分号和斜杠分隔，自动忽略空项与本批重复名称，整批作为一步撤销和自动保存。
- 数据面板支持纯文本三级结构导入与导出。导出提供与 APP 一致的完整树形文字和“仅标签”两种视图，可复制或下载 UTF-8 TXT；完整树形文字可重新导入 Web。导入也支持“分类：/属性：/子属性：”格式、剪贴板、最大 1 MB TXT、实时分类/属性/子属性计数、追加或替换模式。替换会清理旧节点图片引用，但整个操作可一步撤销；不读取 Android 数据库或旧账号项目。
- 数据面板已接入共享的全局标签设置：分类/标签文字和图片显隐、分级描边、色块透明度、字重、可撤销的统一标签色与文字色，以及一键重置。默认字体为系统黑体；资源圆体 Bold 按需加载。用户也可载入最大 20 MB 的本地 TTF、OTF、WOFF 或 WOFF2。Canvas 预览和 PNG 导出等待字体就绪；本地字体保存在独立 IndexedDB 字体库，只随项目保存 ID/名称引用，不上传也不嵌入项目文件，换设备时需重新选择。
- 已迁移 APP 单分类外观设置：分类/标签图片和文字显隐、填充比例、分类/标签描边、系统黑体/资源圆体、字重、分类色、独立文字色，以及无/黑/白/分类色图片遮罩和透明度。分类字段使用可选覆盖值，未设置时继承全局，一键“跟随全局”可删除覆盖；同一画布允许分类混合字体，Canvas 预览和 PNG 使用相同解析。
- 已迁移 APP 当前的全局“分类显示”开关，不保留旧版单分类 `isMultiLayerMode`。开启时一级分类作为容器、二三级在内部布局；关闭时一级分类圈完全移除，二级属性成为顶层独立圆，三级仍保留在各自二级属性内部。该设置进入撤销重做、自动保存和项目文件，基础/重力布局、Canvas 与 PNG 共用同一结果。
- 已接入 APP 同款本地资料板块：可爱日记 3 个、工业风 2 个资料子模板直接使用作者原始配置与素材；支持头像/昵称独立显隐、男/女/无性别、0–4 个标签、模板文本块和可在画布拖动的自定义文字。自定义文字包含字体、字号、字重、旋转、宽度、颜色与描边，预览和 PNG 共用 Canvas 绘制。头像复用项目图片 Blob、撤销重做、自动保存、项目文件和 PNG 导出；没有账号自动载入、“我的主页”、社交或服务器逻辑。
- 已接入自定义、可爱日记和工业风三款带版本号的本地模板；模板只更新画布尺寸、背景和默认标签范围，不替换用户分类、节点或图片，并可作为一步历史撤销。可爱日记和工业风锁定画布比例与尺寸，切回自定义后才能调整。
- Canvas 和数据模型已支持归一化标签范围（位置、宽高和旋转）；经典画布默认使用整张画布，最终圆群会保持正圆与碰撞关系并等比贴合模板范围。范围参数已并入共享外观面板，独立范围入口已移除；进入外观时不自动显示范围边框，只有在画布分段点击“显示调整框”后才显示，切走分段或离开外观会自动关闭，且不会进入 PNG。显示后可按 APP 方式拖动框内移动整体、拖四角同时调整宽高、拖边框单独调整一边；旋转后的命中和拖动增量会转换到局部坐标，范围保持在画布内，连续拖拽合并为一步撤销。
- PC 与移动端共享外观面板，提供经典竖版、3:4、9:16、1:1、4:3 比例和 320–4096 像素自定义尺寸，以及背景快捷色、自定义背景色和基础描边；修改内置模板外观后转为自定义画布，导出尺寸同步更新。
- 已迁移 APP 当前实际使用的 5 个作者装饰素材：日记装饰、FOX、hosi、喵铺和 PP。共享外观面板支持全部/元素/背景筛选、多素材叠加、模板背景显隐，以及 APP 的棋盘格/圆点/网格背景图案和最多 20 个自定义矩形；图案与矩形支持主要尺寸、位置、旋转、颜色和描边参数并进入 Schema、自动保存、撤销重做、项目文件及 PNG。
- 已支持最多 20 张自由本地装饰图片，不再保留语义重复的“本地背景图片”入口。每张图片独立保存名称、显隐、归一化位置、相对大小、旋转和透明度，渲染时保持原始宽高比；在外观中选择后可直接在画布拖动定位、用右下角手柄缩放、用顶部手柄旋转。移动端支持双指中点平移、捏合缩放与夹角旋转的组合手势；单指和双指连续操作均合并为一步撤销。
- 外观面板已加入统一图层列表，属性图、预设素材、背景图案、自定义矩形、自定义图片和资料自定义文字共享从前到后的顺序，支持显隐、按住拖拽排序、上下移动和删除；拖动手柄获得焦点后也可用上下方向键排序。模板背景作为固定底层单独显隐。图层列表与画布图片、矩形和文字共享互斥选择状态，画布按最前可见图层命中；矩形可在画布移动并从四角缩放。画布获得焦点后，选中的图片、矩形和自定义文字可用方向键移动 1 像素，Shift + 方向键移动 10 像素，连续操作进入可合并的撤销记录。图层顺序进入自动保存、撤销重做、项目文件、Canvas 与 PNG。项目仍处于初步开发阶段，后续 Schema 调整不为未发布的编辑数据保留迁移分支。
- 外观面板内部已整理为装饰、图层、画布三个置顶分段，不增加移动端主入口。图层列表显示元素自身显隐与统一隐藏状态的合并结果，点击关闭状态可直接恢复显示；选中图片或矩形后提供参数区快捷入口，文字图层明确提示在资料面板继续编辑。
- 已完成编辑历史：项目名、背景以及同一节点同一字段在 900 毫秒内的连续输入合并为一步，结构和图片操作独立入栈，最多保留 60 步；撤销重做同时恢复文档、选择和图片资产，并触发本地自动保存。
- 顶栏提供移动端可用的撤销重做按钮，同时支持 `Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z` 和 `Ctrl/Cmd+Y`。
- 在线搜索已完成可用闭环：Bangumi 支持角色、动画、游戏和歌手候选；角色与动画也可手动切换 AniList，或使用 Bangumi 返回的日文原名重搜。角色结果显示关联原作；角色搜索可进入“按作品查找角色”，先搜索动画、游戏或书籍，明确选择作品后再显示角色，并可恢复进入前的角色搜索。游戏小字优先英文，歌手小字优先日文。Bangumi 结果采用自适应瀑布流，首批显示 6 张并在滚动到底部后每批增加 6 张；角色和歌手图片顶部聚焦，动画和游戏图片居中。选择 Bangumi 角色或动画结果后，图片调整窗口会保留 Bangumi 原图并加载 AniList 候选；从调整窗口返回搜索时仍可进入自定义内容，同一节点会恢复候选与上次搜索界面。选中图片先下载为 Blob、校验格式和 15 MB 上限，再进入非破坏式调整与 IndexedDB 自动保存。资产保存提供方、外部 ID、来源页、原始图片地址和获取时间。网关只允许固定搜索、固定作品角色查询与 `lain.bgm.tv/pic/` 图片，不是任意 URL 代理。

## 当前阶段结论

- 核心 MVP 功能已齐备，接下来以视觉微调、移动端真机、响应式与可访问性验收为主，不宜继续同时扩张新功能。
- 前端生产构建由 `npm run build` 生成 `dist/`，仓库尚未配置阿里云主站或 Cloudflare Pages 自动部署。
- 正式 Bangumi 网关域名为 `https://bangumi-api.acg-dna.top`；其源码、部署和凭据均在本仓库外维护。前端改动不得覆盖或重建该服务。
- GitHub 仓库仍保持 Private。公开前必须完成素材许可证、安全扫描、演示数据和第三方图片复核。

## 在线搜索关键结论

详见 ONLINE_IMAGE_SEARCH.md。不可忽略的结论：AniList API 和图片 CDN 可用于浏览器 Blob/Canvas；Bangumi API 可跨域，但其图片 CDN 当前会污染 Canvas。不要通过 no-cors 或未知公共代理绕过。

AniList 当前降级到每分钟 30 次请求，代码必须以响应头为准并处理 429。其条款禁止把 API 当备份数据库或批量囤积数据。

## 安全与许可

- 不复制 Android 的 BackendApiConfig、keystore.properties、local.properties、数据库备份、QQ SDK、云函数或 SQL。
- 仓库当前不具备个人私有仓库的 GitHub Secret Protection；公开后 Secret Scanning 会免费运行。私人阶段继续使用本地扫描和严格 .gitignore。
- 资源圆体已无损转换为 WOFF2 并附 SIL OFL 1.1；公开仓库时应保留清晰的字体来源和许可证副本。
- Bangumi 派生数据公开前补齐来源、生成日期和 CC BY-SA 许可说明。
- 原创图形/模板还需要确定独立的素材许可证；不要擅自假设 MPL-2.0 自动覆盖商标和所有二进制素材。

## 禁止事项

- 不恢复账号、发布、社交、关注、通知或相似度功能。
- 不为搜索功能引入隐藏服务器或密钥。
- 不把整个 Android 工程或 reference 目录提交到 Web 仓库。
- 不直接把不支持 CORS 的远程图片画入 Canvas。
- 不在没有测试的情况下重写全部布局算法。
