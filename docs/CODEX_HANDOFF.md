# 开发架构说明

## 目录

- `src/model`：版本化属性图数据模型与校验。
- `src/store`：共享 Editor Store、撤销重做、自动保存和项目状态。
- `src/canvas`：Canvas 预览、PNG 导出、命中测试与布局调用。
- `src/layout`：基础聚合和重力碰撞布局。
- `src/components`：模板、数据、资料、外观、搜索和图片调整面板。
- `src/editor`：图片 Blob、本地字体、IndexedDB 与项目文件读写。
- `public`：随 Vite 构建复制的静态图标和字体资源。

## 数据与保存

属性图文档含 Schema 版本、画布、标签、资料、装饰、图层和显示设置。本地图片作为 Blob 存入 IndexedDB，Bangumi 图片保存受限的 `https` 远程链接；两者都由资源 ID 引用。`.acgdna.json` 会分别携带本地图片数据或远程链接，便于跨浏览器导入。

每个项目独立保存，切换、复制、删除和导入不会覆盖其他项目。自动保存会清理当前项目不再引用的图片；撤销重做同时恢复文档、选择状态与资源引用。

## 渲染与布局

Canvas 2D 是预览与 PNG 导出的共同渲染入口。布局使用稳定种子，保证相同文档得到一致结果。重力布局对顶层分类、属性和子属性递归进行圆形碰撞、边界约束和向下沉积；包含子标签的容器标题以碰撞体参与计算，避免文本压住相邻标签。

画布操作和面板编辑都通过同一 Store 修改数据，因此 PC 与移动端使用同一组组件和业务逻辑。

## 本地资源

- 用户图片、头像、装饰图片和本地字体只留在浏览器。
- 图片采用非破坏式变换，原始 Blob 与裁切、位置、缩放、旋转参数分别保存。
- 内置资源圆体仅在用户选择时加载；本地字体不上传，也不嵌入项目文件。

## 在线图片

浏览器直连 Bangumi 官方 API 和图片源，AniList 作为备用，使用边界见 [在线图片与版权说明](ONLINE_IMAGE_SEARCH.md)。不得添加任意 URL 代理、密钥、账号逻辑或新的服务端能力。

## 开发要求

- 全部文件使用 UTF-8；禁止 GBK、ANSI 与 Windows-936。
- 保持无账号、无云同步、无相似度计算、无公开作品库的产品边界。
- 不提交密钥、数据库备份、真实用户数据或未经授权的第三方素材。
- 修改共享数据模型、保存、布局、渲染或在线搜索时，应补充相应测试。
- 运行 Git、npm、测试、构建命令时，以本仓库根目录为工作目录。
